# 阿尔法筹建自查与未通过项

本文件记录同一助手的代码自查及程序验证，不冒充十四个真实模型的交叉审查。

## 已通过自查修复

- 发现“来源列表”可由模型自报：新增原生 tools/result 观察，将全文读取回执绑定具体子Agent，只搜索/其他Agent读取/失败抓取均不满足研究读取门槛。
- 发现同一模型可换两个路由名字：以 canonicalModelId 和实际 provider/model 双重检查同模配对，仍注明底层网关真实映射依赖管理员核验。
- 发现 Skill 哈希清单不能阻止添加未审资源：新增保留前缀目录与资源清单校验，新增文件必须重新审查。
- 发现创建快照失败可能留下锁：补充失败清理测试，拒绝静默覆盖已有运行。
- 发现单元适配器测试不能证明 DSH 接通：增加真实 headless profile、工具分发、fresh 子调用、不同测试模型覆盖和取数回执的集成烟雾测试。响应仍为夹具。
- 原生烟雾测试首次暴露 fixture 对系统消息位置、文本块合并、agent/created事件字段的错误假设；修正测试集成代码后通过，没有跳过失败检查。

## 尚不能声称完成

1. 未绑定用户提供的真实模型池，未运行真实联网多模型业务试点，未校准主影搭配。
2. 默认能力是只读研究和结构化设计，不含自动安全执行新代码、安装第三方Skill或业务团队试跑器。
3. 未实现跨重启自动恢复、常驻影子、多轮用户变更广播和过程内重大风险即时消息；现有快照用于诊断而非自动重放。
4. 委派上限不是总token或美元硬限额，缺少实际用量网关前必须依赖服务商预算控制。
5. 当前输出结构和来源读取检查不是研究深度的充分证明，仍需真实产物、负对照、人工校准和留出用例。
6. 完整仓库回归与生产就绪未由本改动重新宣称；新增代码隔离于可选alpha扩展，未改动核心循环和依赖锁。

进入下一阶段的必要材料是实际模型路由配置、联网工具配置和授权试点；不需要把密钥发送到聊天或提交到仓库。
