# 能力研发与准入
先登记gap：目标能力、硬条件、已搜索的解决方法、现有候选不适用的原因。未找到只表示当前检索范围内未找到，不表示不存在。
提出可证伪假设，定义最小原型、成功判据、成本上限和失败停止条件。复用原始许可允许的内容并注明来源；下载和编写的内容一律先作为candidate，不因作者自称成熟直接启用。
对照无Skill/现成Skill/新Skill，在相同资料和资源条件运行。保留不参与调优的验收样例，以及无缺陷负对照；比较实际产物、误报、改坏、返工与总资源。
只有工具真实执行并产生可复核记录才写tested。没有沙箱、密钥或外部接口时可以输出原型代码和实验计划，但必须标记not_executed；说明文件不能冒充已接通能力。
脚本、安装包及远程MCP端点需人工授权或已批准策略；限制网络、文件路径和凭证。新能力无法自行更改预算、认证、检查标准或正式Skill库。正式采用后锁定整个能力包hash和依赖版本。
