# 同步预研和独立审查
同一岗位使用同一需求版本的两个独立上下文。影子与主任务同时进入调度，先独立研究证据、反例、时效和检查框架；预研不读取主稿、不接受主稿自评分，不需要第二份成品。
预研输出内部核验资料：coverage、sources、checks、uncertainties。检查准备充分即可ready，不必持续空转。程序应预留完整主影批次，不能先耗尽预算再不启动影子。
主稿提交后才向影子提供对应版本及其hash。影子用自己的预研和实际证据检查，输出verdict与具体findings。每项写明目标、severity、依据、影响和check；允许零缺陷通过，禁止每次必须挑出N个问题。
主方可以修订或提供反证。已证实缺陷、待证风险、可选建议分别处理；审美争议回到用户偏好。不得通过修改要求、放宽测试、增加skip来制造通过。
审核仅绑定subjectHash。版本变化后重新审查相关部分。需要更多实验则blocked并请求调度；达到修订轮数上限不能自动放行。最终整体试跑与人工批准独立于岗位审查。
首版运行器使用一次性原生DSH子调用：预研与正式审查是同一逻辑影子的两次独立调用，正式审查显式携带预研记录；不是已实现常驻可续聊影子。重大风险以结构化结果呈现，过程内消息通知属于后续扩展。
